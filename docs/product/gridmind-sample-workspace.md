## First visitor journey

Open `/explore`, choose **Start Exploring**, then register Press 03 under Machines & Resources. Create a compatible order under Production & Materials. Open a machine-stop investigation against Press 03, evaluate alternatives, inspect sources/constraints, record a simulated review and unresolved/simulated outcome, and export the SYNTHETIC report. The affected order follows actual operation/work-order relationships; the other press/order is not arbitrarily affected. Build a Sample Factory changes this same fictional organization, not a second scenario engine.

The canonical fictional organization is **GridMind Example Components**, **Example Components Plant 01**, **Demo Operations Manager**. Its in-memory IDs never confer real memberships. Refresh/leaving Explore resets records; switching its child URLs preserves records and unfinished forms. A missing session-created deep link explains the reset rather than substituting another record. Reset clears records, drafts, reviews and outcomes. Preferences remain non-sensitive browser settings.

## Evidence and operating limitations

Initialization recipe bytes live at `data/industrial-core/sample-organization-source.txt`, with a tested SHA-256. Each fictional source mutation gets a command digest chained to the preceding source digest. Changed entities and physical links point to that command; frozen evaluations retain their original core/specification/source binding. Timestamps use an explicitly fixed historical replay clock, not measured occurrence time. A hash demonstrates byte integrity, not authenticity or professional attestation. UI source cards explain the fixture-only meaning of core `verified` flags.

The existing typed industrial core, physical dependency evaluator and finite planner perform the calculations. Two presses have distinct orders/materials with shared operator/tool capacity. Material/quality holds, explicit downtime, reservation conservation, mandatory requirements, owner intent and uncertain electrical observations remain separate. The heuristic is conservative, not optimal; unrelated blocked jobs may prevent accepting a whole-plant alternative. It does not dispatch, reserve real inventory, diagnose an electrical cause, authorize machinery, measure savings or prove Indian automotive performance. New sample values are illustrative inputs, never public measurements.

Sample mutations and exports run locally. They do not call privileged industrial-core endpoints, persist to Supabase, create real businesses or change Auth/security/migrations. Personal metadata updates use existing Supabase Auth; memberships remain RLS-protected and read-only. A stored selected factory identifier is revalidated against the current user and freshly authorized factories. Neither metadata nor browser preferences grant access.

## Sample record discovery completion

The header's **Find sample records** opens a keyboard-accessible record palette (Ctrl/Cmd+K outside editing controls). Search combines all words across record name, identifier and type; type and favorites/recent filters compose. Section shortcuts preserve the existing routes. Inspect opens a shared read-only side panel with the existing relationships and evidence cards; investigations link to their exact full workflow. Missing/deleted records cannot resolve to another record.

Favorites and up to eight recently opened records remain in component memory, are pruned against the current sample, and clear on reset, reload or leaving Explore. Nothing is written to browser storage or Supabase. The panel and palette reuse existing Dialog/Sheet/Input/Button components, fonts and green tokens. These interfaces are functionally ready for Lovable refinement; authenticated/private record search remains outside this fictional sample feature.
